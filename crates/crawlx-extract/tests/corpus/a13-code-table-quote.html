Rotating Log Files Without Losing a Line

A busy service writes thousands of lines a minute, and the usual advice to stop the process before rotating is not acceptable when the service must stay up. The safer approach is to rename the file and ask the writer to reopen it.

mv /var/log/app/service.log /var/log/app/service.log.1
kill -HUP $(cat /run/app/service.pid)
gzip /var/log/app/service.log.1

The script above renames first, so the writer keeps appending to the same open handle until it receives the signal. Only then does it switch to a fresh file, which means no line is written to a deleted file.

Whatever method you pick, test it under load. The copy approach looks harmless on a quiet machine and only shows its losses when the service is writing at full speed.

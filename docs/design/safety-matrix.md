# Safety admission matrix

The hard safety kernel (`crawlx-safety`) classifies every proposed browser action into a
risk class and decides it against the run's safety profile. The result is one of three
words:

- `allow`: the action may proceed.
- `approval`: the action is parked until an operator approves it; the crawl continues
  with other work. An approval never turns a hard deny into an allow.
- `deny`: the action is refused.

Text in parentheses is a condition. When the condition is not met the cell narrows to
`deny`. `authorized_security_test` additionally requires a resolvable authorization
record naming target, scope and validity window; without one the run is rejected at
admission. Robots policy is not authorization.

The table below is the kernel's own rendering of its default rule table with every
request option opted in. It is generated by `crawlx_safety::risk_matrix_markdown()`, and
`crates/crawlx-safety/tests/matrix_doc.rs` fails when it differs from the kernel. After
changing the rule table, regenerate it:

```sh
CRAWLX_BLESS=1 cargo test -p crawlx-safety --test matrix_doc
```
